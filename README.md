# Shmsan Views

يسحب منشورات قناة `@shmsannews` ويعالج الروابط المؤهلة مباشرة عبر نموذج الموقع باستخدام Playwright.

## الإعداد
أضف أسرار الحسابات الثلاثة من Settings > Secrets and variables > Actions:
- الحساب 1: `SITE_USERNAME_1` و`SITE_PASSWORD_1`
- الحساب 2: `SITE_USERNAME_2` و`SITE_PASSWORD_2`
- الحساب 3: `SITE_USERNAME_3` و`SITE_PASSWORD_3`

تشغيل رئيسي يدوي: Actions > Shmsan Views > Run workflow.
إعادة محاولة رابط محدد: Actions > Shmsan Views - Manual Link Retry > Run workflow.

## كيف يعمل
- يبدأ من المنشورات بعد `https://t.me/shmsannews/2292`، ويستبعد الرابط نفسه وما قبله.
- أول تشغيل: يضيف أحدث منشور فقط بعد حد البداية إلى الطابور.
- بعدها: يضيف المنشورات الجديدة؛ يعالج روابط التشغيل الجديد أولاً، ثم بقية الطابور من الأحدث إلى الأقدم.
- يعالج كل تشغيل ما يصل إلى خمسة طلبات كحد أقصى.
- يختار كل تشغيل حسابًا واحدًا للمهمة كاملة بالتناوب: 1 ثم 2 ثم 3 ثم يعود إلى 1. التناوب مشترك بين التشغيلات اليدوية، ويُحفظ مؤشر الحساب التالي في `state/account_rotation.json`.
- يجب ضبط الأسرار الستة للحسابات الثلاثة؛ عند غياب أي سر أو تلف ملف المؤشر، يتوقف السكربت بأمان. ملف المؤشر لا يحفظ بيانات الدخول.
- لا يُسجّل الرابط مكتملًا بعد أول نجاح؛ يعاد في التشغيلات اللاحقة حتى يحقق خمسة طلبات ناجحة إجمالًا. يُحفظ عداد مستقل لكل رابط في `state/success_counts.json`.
- الفشل لا يزيد عداد النجاح. تبقى محاولات الفشل في `state/failed_attempts.json`، ويُتخطى الرابط بعد ثلاث إخفاقات.
- إعادة المحاولة اليدوية تستخدم عدادي النجاح والإخفاق نفسيهما، وترفض الرابط بعد بلوغ خمسة نجاحات أو إذا كان مكتملًا في سجل الإنجاز القديم أو تجاوز ثلاث إخفاقات.
- روابط `state/done_links.txt` الموجودة من الإصدارات السابقة تُعامل كمكتملة ولا يعاد تنفيذها. لا يُعدّل السجل القديم ولا تُحتسب له نجاحات تاريخية غير معروفة؛ يبدأ العد الجديد للروابط غير المكتملة والجديدة فقط.
- يتم تسجيل الدخول وإرسال الطلب من خلال نموذج المتصفح مع النقر البرمجي على زر التأكيد لتجاوز العناصر العائمة.

## تصفير الحالة
احذف الملفات داخل مجلد `state/` (ما عدا `.gitkeep`) لبدء المعالجة من جديد.

التشغيل التلقائي متوقف؛ استخدم Workflow التشغيل المباشر يدوياً عند الحاجة.
